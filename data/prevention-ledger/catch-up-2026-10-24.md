# Prevention catch-up review, 2026-10-24

This is the first catch-up review for the preventive engineering loop.
It classifies every no-mistakes review finding this fleet produced, names the five recurring authoring causes behind them, and ships the first three controls.
Every claim below cites a run id or a finding id from `runs.jsonl`; where the data cannot support a claim, the report says so instead of asserting one.

Capture cutoff: `--until 1792800000` (2026-10-24T00:00Z).
Reproduce with the commands in `SCHEMA.md`.

The 90-day ask covers the whole available history: the no-mistakes state database begins on 2026-10-12, and no run predates the window, so the measured span is the 10 days that exist.
There is no pruned run to recover: the 78 log directories match the 78 run rows exactly, and `recovery_archives` is empty.
What does not exist is older history, so "90 days" here means "11 days, everything there is".

The taxonomy is closed and deterministic.
All 866 findings were classified by reading them once and recording the assignment in `classifications.tsv`, keyed `project`, `branch`, `finding_id`.
No model call runs at classification time, and the exporter never guesses: an unreviewed finding gets a null category plus a `classification:unclassified` gap.

## 3. The five recurring causes

Each cause below is a cluster of findings that share one failing authoring artifact.
Counts are findings; citations are run id and finding id.

### Cause 1: matcher and parser boundaries are discovered by review, not by the author

161 findings land in a matcher, parser, or text-projection module.
140 of them are one task, `job-search-director-experience-rule`, which needed 13 runs and produced exactly one green result.
The same shape repeats in `job-search-location-false-exclusions` (8 findings) and `job-search-filtration-gate-fixes` (12).

Evidence, `01M50XVXE6YPSBFV6F4M1DP9ZB`: `LOC-1` (an event word discards a real role location), `LOC-2` (offsite prose becomes foreign location evidence), `LOC-3` (a retreat sentence still reaches role evidence), `LOC-4` (a title prefix regex rejects periods), `LOC-5` (any `location:` label counts as a header).
Evidence, `01M58WX6QWVXRTK7M2A6N8BNA1`: `review-3` (a 40-character window crosses a sentence boundary), `review-4` (spelled-out quantities stop at thirty), `review-10` (both year patterns require a trailing descriptor).
Evidence, `01M511XDSRREAJ16XRCDFBGHXE`: `empty-test-split`, `anchor-overlaps-test-set`, `boolean-confidence-accepted`, `boolean-operating-threshold`.

The authoring artifact that failed: the `## Firstmate spec` acceptance list named the files to change and the verdicts to produce.
It never named the input distribution the matcher had to survive.
No pre-flight check asked for one, so every unlisted input shape became a review round.

### Cause 2: a stated rule is fixed where it was reported, not at every consumer

243 findings are `missing contract`.
133 of them are explicit re-raises, in the reviewer's own words, of an accepted finding from an earlier round; the top task alone contributes 33.

Evidence, `01M58PGWG1BFYCMSWMJKCNC062`: `RM-049` (a decision left a single-entrypoint requirement incomplete), `RM-056` (an earlier finding still unresolved at the audit), `RM-070` (an accepted cohort criterion still unmet), `RM-098` (an accepted completion rule not applied).
Evidence, `01M5D40A7TAJE6SH5031VS4CB7`: `intent-export-module-still-large`, `intent-export-preparation-still-large`, `intent-export-preparation-still-oversized`.
Evidence, `01M4XRB0G1BWX5S78JA3PH9QHG`: `unrequired-live-score-percentiles`, `unneeded-scalar-calibration-fallback` (the review reached surface the ask never authorized).

The authoring artifact that failed: the `## Firstmate spec` numbered list enumerated the call sites named in the first report and stopped there.
It stated instances, not the invariant, so a fix that satisfied the named instance left sibling call sites untouched, and the next round found them again.

### Cause 3: the change leaves documentation, counts, and navigation stale

89 findings are `stale assumption`; 26 of them name a Markdown file directly.
This is drift the change itself creates, not drift found on arrival.

Evidence, `01M4S6N7RP22JGAGV8V9JTG5E7`: `R5` (a report still says three tests after five exist).
Evidence, `01M4SC2NS2EDAERH2VK3GEX3KX`: `review-7` (the same report still claims 14 tests where 15 exist), `residuals-doc` (a record describes a rule that was removed).
Evidence, `01M511XDSRREAJ16XRCDFBGHXE`: `personal-service-label-in-guide`, `undisclosed-round-state-write`.
Evidence, `01M589PMXX2TFV7VY3FG62B6CB`: `duplicate-navigation-maps` (a new summary repeats the map its own README already owns).

The authoring artifact that failed: the `# Definition of done` carried verification and delivery gates but no stale-facts step, so "the change is finished" never included "and the documents that describe this code are still true".

### Cause 4: the change adds surface the ask never authorized

71 findings are `ambiguous acceptance`; 16 carry an explicit `unrequired`, `unneeded`, or `duplicate` id.

Evidence, `01M58E8PRM1XXP0RV9012YD2SW`: `WB-6` (an alternate pre-label source), `WB-13` (alternate schema and fallback paths), plus `WB-7` to `WB-12` in the same run.
Evidence, `01M511XDSRREAJ16XRCDFBGHXE`: `duplicate-incumbent-option`, `unrequired-offline-teacher-csv-mode`, `extra-row-adjudication-policy`.
Evidence, `01M4XRB0G1BWX5S78JA3PH9QHG`: `unrequired-locked-test-views`, `unrequired-raw-text-columns-evaluation-mode`.

The authoring artifact that failed: neither `## Captain's intent` nor `## Firstmate spec` enumerated what stays out of scope.
A broad captain ask plus no boundary is a licence to add options, and each added option became a decision the reviewer had to ask about.

### Cause 5: tests assert implementation source instead of behavior

19 findings are `missing test/fixture`; 12 of them are tests that read implementation bytes, names, or layout instead of exercising behavior.

Evidence, `01M58E8PRM1XXP0RV9012YD2SW`: `WB-5` (regexes over an Apps Script source file).
Evidence, `01M5B9G5YZXJ924GS6Y7NJRX0Y`: `test-forwarder-thin-source-grep` (proves delegation by grepping source).
Evidence, `01M5BDG3KY5VHX05NXS8J6FMTK`: `facade-identity-test` (asserts object identity).
Evidence, `01M5D40A7TAJE6SH5031VS4CB7`: `architecture-tests-parse-source-only`.
Evidence, `01M5BTSK0KQQ25Z2TBCVGV4K97`: `tuner-structural-tests`.
Evidence, `01M5D5GJD319FFQJV7WJF907QH`: `review-1` (a source-content-only AST assertion).

The authoring artifact that failed: a missing pre-flight check.
The repository states the behavior-only rule in its contributor guidance, and nothing at dispatch or in the brief asks the author to confirm the tests will exercise behavior.

## 4. Authoring defects, reviewer preferences, and environment failures

Three populations, kept apart on purpose.

**Authoring defects: 864 of 866 findings.**
These are findings whose repair changes behavior, a contract, a document that describes behavior, or a test's power to detect a regression.

**Reviewer preferences: 2 findings.**
`01M5AMDMWC2NWD2G82QA547PCW` `overbroad-yoe-response-validation` and `01M5JST7Z0FN3SY89F51219Y5C` `r4-reconcile-full-sweep-window-sort-per-invocation` are the pipeline's own `no-op` dispositions: the reviewer raised them and then recorded that no change was needed.
Nothing else can be separated by rule: the pipeline keeps no preference signal, and the `review_questions` table that would carry a captain's disposition is empty on this host, so the remaining 767 findings cannot be split further without a second reading.
That limit is real and it is why the weekly review measures category shares instead of a preference-adjusted score.

**Environment failures: 45 of 78 runs (57.7%) ended without an authoring signal.**
38 carry `run:environment-failure`: 14 agent executions that did not succeed, 10 wall-clock or invocation-budget stops, 5 provider usage-limit exits, 3 daemon shutdowns, 2 session-create failures, 2 model-at-capacity refusals, 1 missing agent binary, and 1 agent timeout.
Six more are `cancelled: aborted by user`, and one is a push refusal (`01M4W12QRX279G5ZK0J249X2JF`).
None of these is counted as an authoring defect, and none of them is in any denominator above.
That 57.7% is the single largest loss in the pipeline and it is not an authoring problem; it belongs to runtime reliability.

## 5. The three controls shipped

One control per category, only for categories with at least three occurrences, and only the three with the largest shares.
None of the three is enforced by the spawn path in this cycle: firstmate runs the pre-flight before dispatch, and the weekly review reads its adoption record, so a control nobody runs shows up as zero adoption instead of as a flat category share.
Wiring the pre-flight into `bin/fm-spawn.sh` is the deliberate next step once adoption is proven.

### Control 1: `Contract coverage:` line in the brief scaffold

Category: `missing contract` (243 findings).
Mechanism: `bin/fm-brief.sh` now emits a `Contract coverage:` line in every ship and scout scaffold, and `bin/fm-brief-preflight.py` refuses a brief whose line is missing, a placeholder, or names no repository path.
The author must name every consumer or call site the stated rules must hold at, and the validator confirms each named path exists at the base revision.

Traces to: `01M58PGWG1BFYCMSWMJKCNC062` `RM-049`, `RM-056`, `RM-070`; `01M5D40A7TAJE6SH5031VS4CB7` `intent-export-module-still-large`; `01M4XRB0G1BWX5S78JA3PH9QHG` `unrequired-live-score-percentiles`.

Expected movement: `missing contract` falls from 28.1% of findings to 20% or less within two weekly cycles.
Leading indicator: briefs name at least one consumer path beyond the files they plan to edit.

### Control 2: `edge-cases` check in the brief pre-flight

Category: `unsafe edge/rollback` (397 findings).
Mechanism: `bin/fm-brief-preflight.py` detects a named risk surface in the brief (parser, matcher, regex, heuristic, migration, concurrency, cleanup, resume, export, schedule) and then requires an `Edge cases:` line naming at least one concrete input, or an explicit `none`.

Traces to: `01M50XVXE6YPSBFV6F4M1DP9ZB` `LOC-1`, `LOC-2`, `LOC-3`, `LOC-4`, `LOC-5`; `01M58WX6QWVXRTK7M2A6N8BNA1` `review-3`, `review-4`, `review-10`; `01M511XDSRREAJ16XRCDFBGHXE` `empty-test-split`, `anchor-overlaps-test-set`.

Expected movement: `unsafe edge/rollback` falls from 45.8% to 35% or less within two cycles.
Leading indicator: the check fails on the first run of most risk-surface briefs and passes after concrete inputs are added.

### Control 3: `Stale facts:` line in the brief scaffold

Category: `stale assumption` (89 findings).
Mechanism: the same scaffold line plus a `stale-facts` pre-flight check.
The author must name each document, count, version, or navigation file the change makes stale, every named path must exist at the base revision, and `none` is allowed but counted.

Traces to: `01M4S6N7RP22JGAGV8V9JTG5E7` `R5`; `01M4SC2NS2EDAERH2VK3GEX3KX` `review-7`; `01M511XDSRREAJ16XRCDFBGHXE` `undisclosed-round-state-write`; `01M589PMXX2TFV7VY3FG62B6CB` `duplicate-navigation-maps`.

Expected movement: `stale assumption` falls from 10.3% to 6% or less within two cycles.
Leading indicator: substantive changes name at least one stale-facts file.
This is the weakest of the three controls: its enforcement is shape and path existence, not whether the named files were actually updated.
It is the first candidate for retirement under the quarterly rule.

## 7. How we will know within one week

Two things are measurable in one week and one is not, and the difference matters.

**Measurable in one week: mechanism adoption.**
Run `bin/fm-prevention-ledger.py stats` for the new rows and `bin/fm-brief-preflight.py --record state/prevention-preflight.jsonl` on every dispatched brief.
Adoption is a count, not a rate: how many briefs passed all three checks before dispatch, how many failed `edge-cases` on first run and passed after the author added inputs, and how many declared `none`.
The record file is the durable source, so the review does not depend on anyone remembering the week.
If a control is not being exercised, its category share cannot move, and the weekly review says so rather than reporting a flat line as success.

**Measurable in one week: caught defects.**
Every pre-flight failure is a defect caught before a review round.
The weekly review reports that count as the leading indicator for all three controls.

**Not measurable in one week: category-rate movement.**
Only 37 runs in 11 days reached review completion, so a weekly cohort is roughly 25 review-bearing runs.
At that size a shift of eight percentage points is inside sampling noise.
The weekly review therefore reports the delta with its denominator and refuses to call a category "improved" before two cycles, which is exactly the retirement rule's clock.

## 8. Unrecoverable evidence gaps

These are permanent for this corpus, and every one of them narrows a conclusion above.

1. `state/<task>.meta` is gone for 66 of 78 rows, deleted at task cleanup.
   Project is recovered from the no-mistakes repository row instead; task kind and delivery mode are not recoverable.
2. `start_head` is unrecoverable for 47 of 78 rows because the pipeline recorded an all-zero base revision.
   Recomputing a merge base now would be wrong: the pipeline rebases, so today's merge base is not the run's start.
3. `end_head` is unrecorded for 39 of 78 rows: failed and cancelled runs never pushed.
4. `plan_ref` is unrecoverable for 43 of 78 rows: neither the brief nor the backlog item cites a plan.
5. `fix_commits` is unrecorded for 47 of 78 rows: the run never pushed, or the pipeline recorded no usable start revision, or the commit range contained no `no-mistakes(...)` subject.
6. Ask-user decisions are unrecorded for 20 findings (`ask_user:no-recorded-decision:*`).
   The `review_questions` table holds zero rows on this host, so the only surviving records are round selection state (362 answers found) and eight status escalations.
7. Environment failures are per run, never per finding, so no category can be blamed on a harness.
   Only the run count (38, plus 6 cancellations and 1 push refusal) is recoverable.
8. Escaped defects after merge cannot be computed at all, and no proxy exists.
9. The window is 10 days, not 90.
   The state database starts 2026-10-12, so older runs are not pruned; they never existed here, and any claim about a longer trend would be invented.
10. Reviewer preference cannot be separated by rule for 767 findings; only the 2 `no-op` dispositions are provably not defects.
